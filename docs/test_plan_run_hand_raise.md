# run_hand_raise.py テスト方針

## 目的
`src/run_hand_raise.py` とエントリポイント `run_hand_raise.py` の主要な振る舞いを自動テストでカバーし、CLI の分岐や描画補助関数の振る舞いが期待通りであることを確認する。

## 対象範囲
- `draw_dwell_status` 関数の描画ロジック
- `main` 関数の引数解釈、設定値の適用、主要コンポーネントとの連携、入出力処理の分岐
- CLI エントリポイント (`run_hand_raise.py`) の `main` 呼び出し

## テスト戦略
1. **ユニットテスト (描画関数)**
   - ダミーの滞在ステータス辞書を与え、腰位置に応じた円描画と日本語テキスト描画が行われるかを画像ピクセルの変化で検証する。

2. **ユニットテスト (エラー分岐)**
   - 存在しない入力パスを指定した場合に、初期化前に処理が終了し適切なメッセージが出力されることを標準出力の内容で確認する。

3. **統合度の高いユニットテスト (正常系)**
   - 主要依存コンポーネント（`PoseEstimator`、`HandRaiseDetector`、`DwellTimeDetector`、OpenCV I/O、`tqdm` 等）をスタブ化し、`main` 関数が設定値の読み込み結果を用いて各コンポーネントを初期化し、フレーム処理ループで検出・描画・出力を行うことを検証する。
   - CSV と動画の出力を有効化した状態で、スタブに期待通りの呼び出しが発生することを確認する。

4. **CLI エントリポイントのテスト**
   - `run_hand_raise.py` が直接実行された際に `src.run_hand_raise.main` を呼び出すことをモックを用いて確認する。

## 非対象
- MediaPipe や OpenCV による実際の骨格推定／描画結果の検証
- 実ファイル出力を伴う大規模な I/O の統合テスト
- `DwellTimeDetector` や `HandRaiseDetector` のアルゴリズム詳細

## 成功基準
- 上記テストがすべてパスし、既存のテスト群も失敗しないこと。
