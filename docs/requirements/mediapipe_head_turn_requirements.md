# MediaPipe Face Mesh 頭部方向検知システム 要件定義書

## 文書情報

- **作成日**: 2025-01-28
- **バージョン**: 1.0
- **ステータス**: Draft

## 1. ビジネス要件

### 1.1 背景

店舗における来店客の行動分析システムにおいて、顧客が店員を探している・呼んでいる行動を自動検知する必要がある。その第一段階として、頭部の方向（左向き・右向き・正面）を高精度で検知するシステムが求められている。

### 1.2 目的

- **高精度な頭部方向検知**: MediaPipe Face Meshの468個の顔ランドマークを活用し、YOLO11 Poseよりも高精度な頭部方向検知を実現する
- **店員呼び出し行動の検知**: 連続した頭部の動き（首振り）を検知し、店員を探している行動をリアルタイムで通知する
- **閾値の最適化**: 正解データ（annotations.csv）に基づいて、検知アルゴリズムの閾値を最適化する

### 1.3 期待される効果

- 店員呼び出しの検知精度向上（現状のYOLO11 Pose比）
- 顧客の待ち時間短縮
- 店員の業務効率向上

## 2. 機能要件

### 2.1 頭部方向検知機能

#### FR-001: MediaPipe Face Meshによる顔検出
- **説明**: 動画フレームごとにMediaPipe Face Meshで顔を検出し、468個のランドマークを取得する
- **入力**: 動画フレーム（RGB画像）
- **出力**: 顔ランドマーク（468点）、検出信頼度
- **制約**: 
  - 信頼度が閾値（デフォルト0.5）以上の場合のみ有効とする
  - 複数の顔がある場合は最も信頼度の高い1つを選択

#### FR-002: ヨー角（Yaw angle）計算
- **説明**: 顔ランドマークから頭部の左右方向の角度（ヨー角）を計算する
- **入力**: 顔ランドマーク（468点）
- **出力**: ヨー角（度数法、-180度〜+180度）
- **計算方法**:
  - 鼻先（Landmark #1）、左耳（Landmark #33）、右耳（Landmark #263）を使用
  - 耳の中点からの鼻先のオフセット比率を角度に変換
  - 正の値: 右向き、負の値: 左向き、0付近: 正面

#### FR-003: 頭部方向の判定
- **説明**: 計算されたヨー角から頭部の方向を3つのカテゴリに分類する
- **入力**: ヨー角
- **出力**: 方向カテゴリ（"正面" / "左向き" / "右向き"）
- **判定基準**:
  - 右向き: ヨー角 >= `yaw_threshold_right`（デフォルト20度）
  - 左向き: ヨー角 <= `yaw_threshold_left`（デフォルト-20度）
  - 正面: 上記以外

#### FR-004: 連続フレーム検知
- **説明**: 同じ方向が連続して検知された場合に「持続的な方向転換」として通知する
- **入力**: フレームごとの方向カテゴリ
- **出力**: 持続的方向転換イベント（方向、継続フレーム数）
- **判定基準**:
  - 連続`min_consecutive_frames`フレーム以上（デフォルト3フレーム）
  - クールダウン期間（デフォルト10秒）内は再通知しない

### 2.2 出力機能

#### FR-005: コンソールログ出力
- **説明**: 持続的方向転換が検知された際にコンソールにログを出力する
- **出力形式**: `[MediaPipe] Sustained turn detected: {direction}, frames: {count}, timestamp: {time}`

#### FR-006: ビデオへの視覚化
- **説明**: 検知結果を動画フレーム上にリアルタイムで描画する
- **描画内容**:
  - 現在のヨー角（数値）
  - 現在の方向（色分け: 左=青、右=赤、正面=緑）
  - 持続的方向転換検知時の大きなアラート表示
  - 日本語/英語切り替え対応

#### FR-007: CSV出力
- **説明**: フレームごとの検知結果をCSVファイルに記録する
- **出力カラム**:
  - `mediapipe_yaw_angle`: ヨー角
  - `mediapipe_face_detected`: 顔検出フラグ
  - `mediapipe_turn_direction`: 現在の方向
  - `mediapipe_sustained_turn_detected`: 持続的方向転換フラグ
  - `mediapipe_sustained_direction`: 検知された方向
  - `mediapipe_sustained_frames`: 継続フレーム数

### 2.3 閾値最適化機能

#### FR-008: 正解データとの照合
- **説明**: 正解データ（annotations.csv）と検出結果を比較し、最適な閾値を計算する
- **入力**: 
  - annotations.csv（VideoID, Timestamp, ActionLabel）
  - 検出されたヨー角
- **出力**:
  - ActionLabelごとのヨー角統計（平均、標準偏差、最小・最大値）
  - 推奨閾値
  - Markdownレポート

#### FR-009: 評価指標の計算
- **説明**: 検出結果の精度を定量的に評価する
- **評価指標**:
  - フレームレベル: Precision, Recall, F1-Score, Accuracy
  - 混同行列（正面/左向き/右向き）
- **出力**: Markdownレポート

## 3. 非機能要件

### 3.1 性能要件

#### NFR-001: リアルタイム性
- **要件**: 30fps動画の場合、1フレームの処理時間は33ms以内
- **測定方法**: 処理時間のログ出力とプロファイリング

#### NFR-002: 精度
- **要件**: 
  - 正解データに対するF1-Score: 0.8以上
  - 誤検知率（False Positive Rate）: 0.2以下
- **測定方法**: 評価スクリプトによる定量評価

### 3.2 保守性要件

#### NFR-003: コードの可読性
- **要件**: 
  - 既存の`PostureAndMotionDetectorBase`を継承
  - `HandRaiseDetector`と同様のアーキテクチャ
  - ruffによる静的解析でエラーなし
  - 日本語ドキュメント完備

#### NFR-004: テスタビリティ
- **要件**:
  - ユニットテストカバレッジ: 80%以上
  - 各メソッドが独立してテスト可能

### 3.3 互換性要件

#### NFR-005: 既存システムとの統合
- **要件**:
  - 既存の`VideoProcessor`にオプション機能として統合
  - YOLO11 Poseとの併用が可能
  - 既存のCSV出力形式を破壊しない

### 3.4 拡張性要件

#### NFR-006: 将来の機能拡張
- **要件**:
  - 複数回の首振りカウント機能への拡張が容易
  - 他のジェスチャー（うなずき、手を上げる）との統合が容易
  - パラメータ（閾値、フレーム数）の外部設定対応

## 4. 制約条件

### 4.1 技術的制約
- MediaPipe 0.10.x以降を使用
- Python 3.11以上
- OpenCV 4.x以上

### 4.2 データ制約
- 入力動画: MP4形式、解像度640x480以上
- 正解データ: CSV形式（VideoID, Timestamp, ActionLabel）

### 4.3 環境制約
- macOS / Linux環境での動作を保証
- GPUは不要（CPU処理のみ）

## 5. 用語集

| 用語 | 説明 |
|------|------|
| ヨー角（Yaw angle） | 頭部の左右方向の回転角度。正の値は右向き、負の値は左向き |
| MediaPipe Face Mesh | Googleが開発した顔ランドマーク検出ライブラリ。468個のランドマークを高速に検出 |
| 持続的方向転換 | 連続した複数フレームで同じ方向が検知される状態 |
| クールダウン期間 | 一度検知した後、再検知を抑制する期間 |
| PostureAndMotionDetectorBase | 本プロジェクトの姿勢・動作検出器の基底クラス |
